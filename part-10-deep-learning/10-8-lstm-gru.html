10.8 LSTM and GRU

10.7 ended on a diagnosis: the recurrent update multiplies the gradient by \(D\,W_h\) every step, so long-range credit assignment decays or explodes. LSTM (and its leaner cousin GRU) re-engineer that update: multiplicative gates decide what to forget, write, and expose, and an additive cell state gives gradients a near-constant path through time. This page builds the gates by hand and watches memory survive 100 steps — live in NumPy.

Tier 3 — the PyTorch nn.LSTM/nn.GRU lab runs in Colab; the gate mechanics below run live:

1. Basic Concept

The LSTM cell keeps two vectors: hidden state \(h_t\) (what it exposes) and cell state \(c_t\) (what it remembers):

\[ \begin{aligned} f_t &= \sigma(W_f[h_{t-1}; x_t] + b_f) &&\text{forget gate} \\ i_t &= \sigma(W_i[h_{t-1}; x_t] + b_i) &&\text{input gate} \\ \tilde c_t &= \tanh(W_c[h_{t-1}; x_t] + b_c) &&\text{candidate} \\ c_t &= f_t \odot c_{t-1} + i_t \odot \tilde c_t &&\text{additive update} \\ o_t &= \sigma(W_o[h_{t-1}; x_t] + b_o) &&\text{output gate} \\ h_t &= o_t \odot \tanh(c_t) \end{aligned} \]

The gradient through the cell state is \(\partial c_t / \partial c_{t-1} = \mathrm{diag}(f_t) + (\text{gate terms})\) — when \(f_t \approx 1\) and writes are gated off, the derivative passes at ≈ 1 per step: the constant error carousel. Memory decays (or persists) by learned decision, not by forced multiplication.

GRU merges the two states and three gates into two (\(z\) = update, \(r\) = reset):

\[ \begin{aligned} z_t &= \sigma(W_z[h_{t-1}; x_t]), \qquad h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t \end{aligned} \]

Same idea — convex blend between old state and candidate — with ~25% fewer parameters.

Worked example — gates as arithmetic, memory by construction:

The vanilla state is gone (multiplied by ≈0.9 one hundred times); the gated cell survives by choosing not to forget. Training sets those choices.

2. Concept Questions

  1. \(\partial c_t/\partial c_{t-1} = \mathrm{diag}(f_t)\) when the candidate term is ignored. Why is additive + diagonal the crucial pair — what breaks if the update were \(c_t = \tanh(W_c c_{t-1} + \ldots)\) (i.e., a vanilla cell with forget-gating painted on)?
  2. All gates are sigmoids initialized near 0.5, but practitioners initialize the forget-gate bias to +1 or +2. What failure does this default prevent, and why doesn’t the same trick help the vanilla RNN?
  3. Count LSTM parameters for input dim \(d\), hidden size \(h\); same for GRU. At \(d = h = 128\), what is the ratio — and what does each parameter buy in the gate story?
  4. GRU has no separate output gate. What replaces \(o_t\)’s job, and when does that matter (which tasks miss the output gate least)?
  5. The cell state is exposed to the output through \(\tanh(c_t)\) but the recurrent path carries \(c_t\) raw. What breaks if you feed \(\tanh(c_t)\) forward as the next cell state instead?
Answers
  1. Product of Jacobians again: \(D_c W_c\) multiplies per step — same vanishing disease with extra steps. The fix works because (a) addition doesn’t shrink (gradient +1 path), (b) diagonal means each memory channel decays independently at its own learned rate — no cross-channel mixing to compound. Gating a multiplicative cell only slows the disease.
  2. With random init, forget gates start ≈ 0.5 → memory half-life of ~1 step → early training sees only local gradients and never discovers long memory (a chicken-and-egg: long-range credit is needed to learn long-range memory). Bias +1/2 starts gates ≈ 0.73–0.88 → multi-step memory from step one, so the gradient that would reward remembering exists. The vanilla RNN has no gate to bias — its per-step factor is structural (\(D W_h\)), not a parameter.
  3. LSTM: \(4(dh + h^2 + h)\) (4 gates × weights, recurrent block, biases); GRU: \(3(dh + h^2 + h)\). At 128/128: LSTM 131,584 vs GRU 98,688 — ratio 4:3. Each gate buys one decision channel over the same memory: LSTM spends the extra on separating “what to erase” from “what to write” and “what to show”.
  4. The GRU’s exposure is fixed: \(h_t\) is always the (blended) full state. Tasks that read every step (sequence labelling, language modeling) barely miss \(o_t\) — the update gate \(z_t\) already modulates exposure indirectly. Tasks that must store something while emitting something unrelated (rare, e.g., certain pointer/memory tasks) lose the cheapest mechanism for it.
  5. Then the gradient path picks up the tanh slope again (\(\tanh' \le 1\), ≈ 0 near saturation) — you’ve rebuilt a (softer) multiplicative bottleneck and reintroduced vanishing. The cell’s raw linear highway is the point; \(\tanh(c)\) is only the readout squashing.

Exercises (with solutions)

Exercise 1. Minimal LSTM cell in NumPy: implement the six equations vectorized for one sequence, with weights you set by hand (not trained): (a) a “rememberer” (\(f{=}1, i{=}0\)) that stores the first input and ignores the rest; (b) an “accumulator” (\(f{=}1, i{=}1, \tilde c{=}x\)) that sums inputs into the cell; (c) a random-weight cell for contrast. Feed each a 50-step sequence and plot \(c_t\), \(h_t\). Which hand-set cell solves “output the first token” — the task where 10.7’s vanilla RNN demonstrably fails?

Solution
The rememberer’s input gate is h-gated: the first pulse writes itself into \(c\) and the resulting \(h\) slams the gate shut against later ones — memory doing its own access control, which is exactly why the input gate reads \(h_{t-1}\). Nothing here was trained: the gate parameterization makes “store one thing, ignore the rest” a representable, easy-to-reach configuration — which is why optimization finds it where the vanilla RNN’s multiplicative dynamics can’t even express it.

Exercise 2. Gradient autopsy, gated vs vanilla: for the Exercise-1 rememberer and for a random vanilla cell (\(h_t = \tanh(W h_{t-1})\), \(\rho(W) = 0.9\)), compute \(\partial c_T/\partial c_0\) (or \(\partial h_T / \partial h_0\)) numerically — perturb \(c_0\) (or \(h_0\)) and measure output change — for T ∈ {10, 30, 100}. Report the three magnitudes. Then set \(f = 0.9\) in the LSTM and redo: what half-life do you measure, and does it match \(\ln 0.5 / \ln f\)?

Solution
With \(f = 0.999\) the 100-step gradient survives at 0.90; the vanilla cell is at \(0.9^{100} \approx 3{\times}10^{-5}\) — four orders of magnitude, from one parameter’s difference. Setting \(f = 0.9\) moves the LSTM’s gradient to exactly \(f^T\): measured half-life 6.6 steps, matching \(\ln 0.5/\ln f\). The cell’s memory is a dial the optimizer turns; the vanilla RNN’s is baked into the spectrum of \(W_h\).

Exercise 3. LSTM vs GRU vs vanilla, trained small: in scikit-learn terms this needs the Colab lab, but the decision table can be built live: for tasks (a) next-step sine (local, T=20), (b) first-token recall (T=100), (c) counting pulses over 200 steps — predict the ranking of vanilla/GRU/LSTM by parameter efficiency and by achievable accuracy, then verify against the qualitative results table below (fill it in the Colab lab with nn.RNN/nn.GRU/nn.LSTM at matched hidden sizes). Which task punishes the parameter-hungry LSTM most, and why is “GRU first” the sane default?

Solution
Expected pattern: on local tasks all three tie and the LSTM’s 4/3 parameter surplus is pure overfit risk (the punishing case) — GRU or even vanilla wins the efficiency argument. On long-range recall/counting, gates are decisive and GRU ≈ LSTM (GRU’s merged state suffices in most benchmarks; LSTM pulls ahead mainly on very long sequences or when separate output/read memory matters). Default: GRU first (fewer params, fewer states to carry, ≈ tied accuracy); upgrade to LSTM only when the task demonstrably needs independent write/erase/read. Vanilla RNN is for teaching pages like this one.

4. Advanced Information & Pitfalls

  • The 4× parameter wall: LSTM layer params are \(4(dh + h^2 + h)\) — doubling hidden size quadruples the recurrent block. On small corpora this is the difference between fitting and memorizing (10.5’s whole toolkit applies).
  • Carry both states: nn.LSTM returns (h, c); saving only h between chunks of a long document silently flushes the cell — the model “forgets the beginning of the paper” mid-stream.
  • Forget-gate bias init (nn.LSTM(..., bias) custom init at +1): the default random init makes early training local-memory-only; the +1 bias is a two-line change with outsized effect on long-sequence tasks.
  • Bidirectional ≠ causal: a BiLSTM reading the whole sequence before emitting \(h_t\) uses future information — fine for tagging a fixed transcript, catastrophic for online forecasting; keep directions straight per task.
  • Output-per-step vs final output: nn.LSTM returns outputs for all t plus the final state; sequence classification wants the final (or a pooled) readout, labelling wants the full series — mixing these silently changes the task.
  • Gradient clipping still applies: gates tame vanishing; exploding survives (long chains × unlucky batches) — clip the global norm (10.7).

Read & Refactor AI Code

This AI-generated stateful inference loop for a trained nn.LSTM has three bugs. Diagnose before opening the fix.

model.eval()
h = torch.zeros(1, 1, H)            # hidden
c = torch.zeros(1, 1, H)            # cell
for chunk in document_chunks:
    out, (h, c) = model(chunk, (h, c))
    probs = torch.softmax(model.head(out), dim=-1)     # BUG 1
    pred = probs.argmax(-1)
    h = h.detach()                                      # BUG 2
    # BUG 3: c is never detached/re-used correctly — see below
    print(pred.item(), probs.max().item())
What’s wrong, and the fix
  1. Softmax then argmax: argmax is softmax-invariant — the softmax wastes compute and, worse, invites using probs as calibrated probabilities (they’re not, absent calibration work — 10.2). Take logits straight to argmax; keep softmax only if you actually need a distribution.
  2. h detached, c carried with graph: c still references the autograd graph, so the “inference” loop grows memory every chunk until it OOMs — the LSTM’s long-term memory is exactly the tensor someone forgot to cut loose.
  3. Inconsistency (the real killer): detaching one state and not the other means the graph alive through c pins every intermediate chunk’s forward activations. Detach both (or run the whole loop under torch.no_grad() — simpler and impossible to get half-wrong).
model.eval()
h = torch.zeros(1, 1, H); c = torch.zeros(1, 1, H)
with torch.no_grad():
    for chunk in document_chunks:
        out, (h, c) = model(chunk, (h, c))
        pred = model.head(out).argmax(-1)
        print(pred.item())

5. Advanced Questions

Q1. Prove the “constant error carousel” claim precisely: for the LSTM with output gate bypassed (gradients w.r.t. \(c_t\) only), show \(\partial c_t / \partial c_{t-1} = \mathrm{diag}(f_t)\) plus a term through the candidate, and derive the condition under which the through-\(\tilde c\) term vanishes. Then show the total per-step Jacobian is lower-bounded by \(\min_s f_s\) over the path — the property no multiplicative cell of the vanilla form enjoys — and explain what the optimizer must do to earn it.

Hint Differentiate \(c_t = f_t \odot c_{t-1} + i_t \odot \tanh(W_c[h;x])\) w.r.t. \(c_{t-1}\): direct path through \(f_t\); indirect paths through \(h_{t-1}\) (which feeds all gates). When do the indirect paths carry zero?
Solution \(\partial c_t/\partial c_{t-1} = \mathrm{diag}(f_t) + \sum_{g \in \{f,i,\tilde c, o\text{-via-}h\}} \frac{\partial c_t}{\partial g_t}\frac{\partial g_t}{\partial h_{t-1}}\frac{\partial h_{t-1}}{\partial c_{t-1}}\). The indirect terms pass through \(h_{t-1} = o_{t-1} \odot \tanh(c_{t-1})\) and every gate’s Jacobian — products of σ′ and tanh′ factors. They vanish when output gate \(o_{t-1} \approx 0\) (cell decoupled from the exposed state — nothing written lately) or when gate gradients saturate. Then the direct path alone gives per-step factor \(f_t \in (0,1)\): the gradient decays at the learned, per-channel rate, and can be held ≈ 1 by \(f \to 1\) — but the optimizer must first receive long-range gradient to want that (hence forget-bias init: seed the property, let gradient refinement keep it). The vanilla cell has no such decoupling: every step’s factor is \(D_h W_h\) regardless of what the task needs.

Q2. Gating vs attention on the copy task: sequence-to-sequence copy (“echo input token 0 after T distractors”) is solvable by an LSTM cell and trivially by attention over inputs. Sketch both mechanisms’ parameter and path-length cost as T grows: LSTM (fixed params, O(T) path, gate-dependent survival) vs attention (O(T) memory for the KV cache at inference, O(1) path). For T = 10³ and T = 10⁶, state which mechanism is viable and why — this is the load-bearing argument for 10.9’s replacement of recurrence.

Hint Count what must persist: LSTM compresses history into h, c (fixed size); attention keeps all tokens (linear memory). Path length: how many multiplicative steps separate token 0 from the output?
Solution LSTM: fixed-size state regardless of T; token 0 must survive T gate steps — survival probability is the product of per-step keep factors; trainable, but at T = 10³ even f = 0.999 leaves \(0.999^{1000} \approx 0.37\) and practical training rarely holds f that close to 1 across all channels. Attention: token 0’s key/value sit in a table; the query reads them in one hop — path length O(1), gradient O(1), no decay; cost is O(T) memory (KV cache) and O(T²) compute per layer. At T = 10³: attention wins outright (10³ scalars is nothing; the LSTM needs learned perfection for 10³ steps). At T = 10⁶: attention’s O(T²) attention matrix and O(T) cache dominate (the reason Part 13’s long-context LLM work exists), while an LSTM’s fixed state is free — but 10⁶-step credit assignment through gates is beyond practical training. Field summary: recurrence scales state, attention scales access; modern sequence models pay memory for access because compute got cheap and data got long.

6. Complex Questions

C1 (× 10.5 × 10.7 clipping). Regularization a gated cell differently: dropout on recurrent connections breaks the memory (the cell reads a zeroed \(h_{t-1}\)) — hence variational/stateful dropout schemes (same mask all steps) vs input/output-only dropout. Design the experiment on the first-token recall task: vanilla dropout vs same-mask-every-step dropout vs no dropout, at two corpus sizes. Which scheme preserves recall while regularizing, and what does the answer generalize to (10.9’ attention dropout — applied where, exactly?)

C2 (× Part 13 LLM concepts × 10.9). Write the two-paragraph design memo: your team must choose between “stacked BiLSTM encoder” and “pretrained transformer encoder (frozen + linear head)” for tagging 10k clinical notes on a single GPU. Cover: parameter/data budget, transfer availability (what exists on the hub for each), path-length vs domain-jargon trade-off, and the decision rule that follows from 10.10. (The honest answer leans on transfer, not architecture — make that conclusion earned by the memo’s numbers.)

7. Summary

  • LSTM: gates (forget/input/output) + additive cell state ⇒ per-step gradient factor is a learned diagonal — memory by decision, not by multiplication.
  • The constant error carousel needs additive updates and a raw linear carry path; tanh-ing the cell state re-breaks it.
  • GRU merges states and gates: 3/4 the parameters, ≈ LSTM accuracy in most benchmarks — the sane default.
  • Forget-gate bias ≈ +1: seed long memory before the gradient can ask for it.
  • Carry both (h, c) across chunks; detach both at inference; bidirectionality is a causality decision, not a free lunch.
  • Gates fix vanishing; attention removes the need for the relay entirely — 10.9 attention and transformers.
