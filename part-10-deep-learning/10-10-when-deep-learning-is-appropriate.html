10.10 When Deep Learning Is Appropriate

You now own the deepest toolbox in the course — which makes the most valuable skill knowing when not to use it. Deep learning wins when structure (images, sequences, language) meets data volume and transferable representations. On modest tabular data, gradient-boosted trees (7.5) remain the strongest default in applied work. This page turns that folklore into measurements you can reproduce live, and ends with a decision rule you can defend.

Tier 1 — this page is concept + light compute; every cell below runs live (scikit-learn only):

1. Basic Concept

The decision axes, in the order they usually matter:

  1. Data structure — is there perceptual/spatial/sequential/language structure for representation learning to exploit, or is it a table of heterogeneous features? Deep nets earn their keep on the former; on the latter their flexibility is variance (4.4).
  2. n, honestly counted — end-to-end representation learning wants 10⁴–10⁶+ examples per concept; below that, either engineered features or transfer (pretrained representations) must supply the structure.
  3. Label cost — DL amortizes best when labels are cheap and abundant; 300 expensive clinical labels argue for a regularized classical model + honest CV (4.3).
  4. Interpretability/regulatory needs — a Cox model’s hazard ratio (11.5) or a tree path explains itself; a 12-layer net gets post-hoc (weak) explanations.
  5. Compute/latency budget — training on Colab is free-ish; serving a transformer per API call is not always.
  6. Transfer availability — the modern unlock: when a pretrained backbone exists for your data type, the bar for DL drops enormously (fine-tune > train from scratch, always).

The MLP closes the gap as n grows but never clearly leads on this generic tabular problem — while costing hyperparameter care the trees didn’t ask for. This is the empirical content of “boosted trees first, DL when structure or scale demands it.”

2. Concept Questions

  1. Your dataset: 800 rows, 40 mixed-type clinical columns, goal = risk prediction for a regulatory submission. Rank the axes above by how decisively each argues, and name the model you defend.
  2. “Deep learning needs big data” is half-true since transfer learning. Restate the constraint precisely: what must be big — and give an example where 100 labeled images suffice.
  3. Why does a 1-parameter-per-feature logistic model underfit the bake-off data while the MLP only matches the trees — where is the MLP’s capacity going that the trees’ isn’t?
  4. You must choose the horizon: deep net trained today vs gradient boosting updated monthly with new data. Which infrastructure costs differ, and which one is more likely to silently rot?
  5. Name a data type where “classical first” is the wrong default, and the classical method people still mistakenly reach for.
Answers
  1. Structure: none perceptual (argues against DL). n: small (against). Labels: expensive (against). Interpretability: required (decisively against). Compute: irrelevant at this size. Transfer: none for heterogeneous clinical tables (against). Defensible choice: regularized logistic/Cox with honest CV; gradient boosting as the accuracy-seeking challenger; the deep net is indefensible here.
  2. The pretraining corpus must be big and structurally aligned; your labeled set can be tiny because representation learning already happened. Example: fine-tuning an ImageNet-pretrained backbone on 100 labeled histology patches, or a pretrained sentence embedder + logistic head on 200 labeled notes.
  3. The MLP spends capacity learning smooth axis-aligned-to-rotated feature geometry that the axis-aligned tree splits get for free on this generative process; the linear model underfits because some informative structure is genuinely nonlinear (interactions). The MLP’s extra capacity is spent re-deriving what trees hard-code — on generic tabular data, that re-derivation is overhead, not insight.
  4. The DL route: fixed architecture, retrain pipeline, GPU access, drift in representation (silent). The trees: cheap retrains, but tree models also rot silently (feature drift → stale splits). The difference is monitoring surface area: classical pipelines are simpler to re-validate; deep pipelines have more places (preprocessing, tokenizer, init) for undetected drift.
  5. Perceptual data with tiny classical feature sets — e.g., raw-audio keyword spotting or pathology images: “logistic regression on 50 engineered features” is the wrong default when pretrained representations exist. People still reach for hand-crafted features + shallow models because the classical toolkit feels safer — the mismatch costs accuracy, not correctness.

3. Drills & Exercises

Drills

Predict, then run.

Exercises (with solutions)

Exercise 1. The bake-off, three generative processes: build three datasets — (a) near-linear signal, (b) pure axis-aligned interactions (target = XOR of thresholded features), (c) smooth nonlinear boundary — at n = 500. Fit logistic, HistGradientBoosting, and MLPClassifier on each; tabulate 5-fold CV accuracy. Verify the folklore ranking per column and explain why each winner wins in one sentence apiece.

Solution
Expected pattern: (a) logistic wins or ties — the truth is in its model class, extra capacity only adds variance; (b) trees dominate — XOR is axis-aligned boxes, exactly what splits express natively while linear/MLP models must compose many units to carve diagonal-oblique boundaries; (c) MLP catches the trees — a smooth ring is not axis-aligned, so the tree must staircase toward it while the net’s smooth activations match the geometry. The decision rule is generative, not tribal: match the model class to the boundary’s geometry and your n.

Exercise 2. Sample-size curves for a structured problem: on the digits dataset, plot test accuracy vs training-set size n ∈ {50, 100, 250, 500, 1000} for logistic regression and an MLP (one hidden layer). Where do the curves cross, what is the asymptotic gap, and how does this justify “DL when structure + data” even for a problem as small as 8×8 images? State what a CNN would add (and why we defer it to Colab).

Solution
Both climb; the MLP starts below (capacity without data = variance) and crosses above as n feeds it, ending 2–5 points ahead — pixels have spatial structure the hidden units partially exploit. The CNN would add weight sharing over that spatial structure (the 10.6 argument) and push another few points — the Colab lab shows it. The full pattern — classical competitive when n is small, representation learning pulling ahead as n grows — is the entire “data + structure” quadrant in one plot.

Exercise 3. The leakage trap, DL edition: feature selection is preprocessing that silently reads \(y\). Compare two protocols on 300 noisy tabular samples with 200 features (p/n > 0.5): (a) SelectKBest(k=10) fitted on the full dataset, then CV of an MLP on the selected features; (b) the selector embedded inside the CV pipeline (re-selected per fold). Quantify the optimism of (a). Then state the general rule this exercise installs — which preprocessing steps must live inside the fold, and where does the early-stopping variant of this trap hide?

Solution
Selecting the 10 most promising columns using all labels hands the validator features pre-screened by the answers — each fold’s test rows influenced their own selection. The inflation grows with p/n and noise (here +0.01; in noisier, wider regimes it reaches several points) — and it is pure profit for doing nothing, which is what makes it dangerous. The rule: any step whose output depends on \(y\) — selection, imputation values, scaling, PCA rotation, tokenizer vocab — lives inside the fold; a Pipeline object is the enforcement mechanism, not bureaucracy (4.3). Early stopping hides the same trap one level deeper: a validation set used for stopping is in the model-selection loop, so the final test estimate must come from data that touched neither training nor stopping.

4. Advanced Information & Pitfalls

  • The default order on tabular data: gradient boosting → regularized linear/GLM → and only then, with evidence, a net. Teams lose weeks tuning an MLP to match day-one boosting accuracy.
  • Small-data DL fails quietly: a 64-unit MLP on 200 rows returns a confident 0.71 accuracy; its seed-variance is ±0.05 — check seed spread before comparing models at all (4.4).
  • Transfer changes the calculus but not the protocol: fine-tuning on 500 images is legitimate; validating it still needs held-out data untouched by model selection.
  • Interpretability is a requirement, not a preference: regulated domains (clinical, credit) demand auditable decision logic — post-hoc saliency maps do not satisfy the same bar as a coefficient or a split path (11.5’s hazard ratios, 7.1’s paths).
  • Serving costs are real costs: a boosted-tree model is kilobytes and microseconds; the transformer is gigabytes and GPU-seconds — match the deployment budget (6.6’s lesson about local models, at industrial scale).
  • The course-wide map: linear/GLM when signal is linear-ish or p ≫ n (5.x); splines/GAM for smooth univariate structure (6.7); trees/boosting for tabular interactions; SVMs for small-n kernel structure (8.4); PCA/clustering to understand (9.2); DL for perceptual/sequential/language at scale with transfer.

Read & Refactor AI Code

This AI-generated plan (not code — worse) proposes the modeling strategy for a new project. Refactor it.

“For our 400-row electronic health records dataset (45 mixed features), I recommend a 6-layer feedforward network with 512 hidden units, batch normalization, dropout 0.3, and heavy data augmentation via feature noise. We’ll tune with a random search over 200 configurations and report the best CV accuracy. A transformer encoder over feature tokens will then capture feature interactions.”

What’s wrong, and the refactor
  1. Capacity vs n inverted: 512-wide layers on 400 rows is memorization hardware; augmentation-by-noise invents patients who don’t exist and can smear real signal.
  2. Tuning as evidence: 200 random configurations selected on CV accuracy is multiple testing on the same small data — the winner’s score is optimistic by construction (12.2); the honest budget is a handful of candidates, nested CV.
  3. Transformer over feature tokens: attention over exchangeable features imposes no useful structure (features aren’t a sequence); it’s architecture cosplay. And “report best CV accuracy” conflates selection with evaluation.
Refactor: gradient boosting as primary model (interactions, mixed types, 400 rows is its home turf); regularized logistic regression as interpretable co-primary for the regulatory readers; a small tuned MLP only if boosting demonstrably stalls and a validation harness (nested CV, seed-replicated) justifies it. Report the protocol, not the best draw.

5. Advanced Questions

Q1. The “no free lunch” made operational: design and run an experiment where each of three model classes wins decisively on data generated to favor it — (a) linear truth with 5,000 features and 300 samples (sparse signal), (b) axis-aligned interaction truth at n = 5,000, (c) smooth rotational boundary at n = 5,000. Fit L1-penalized logistic (5.3’s classification cousin), HistGradientBoosting, and MLP to each dataset; produce the 3×3 accuracy table. Derive the practical rule the table implies (in terms of truth geometry and p/n regime), and state the one property no model in the table has.

Hint Match generative process to inductive bias: sparsity ↔︎ L1; boxes ↔︎ splits; smooth rotations ↔︎ smooth activations. The missing property is omniscience about which regime you’re in — hence validation.
Solution
Expected table: lasso wins (a) by a landslide — L1’s sparsity matches the truth’s; trees win (b) — boxes are native; MLP wins (c) — smooth rotations are native. Rule: infer the truth’s geometry (or try one cheap probe per geometry) and match the bias; never run one model across unknown regimes and extrapolate. The missing property: knowing beforehand which regime you’re in — that’s what honest validation budgets exist to discover.

Q2. Write the transfer-learning decision tree for a new perceptual dataset (say, 2,000 labeled microscopy images, 6 classes): at each node, name the evidence that decides it — (1) does a pretrained backbone for this domain exist? (2) how far is your data from its pretraining distribution? (3) how many labels do you have? (4) latency/privacy constraints? — and end with the three concrete strategies (linear probe, partial fine-tune, full fine-tune) mapped to the branches. Then state the validation design that must accompany each branch (what can leak, and where).

Hint The tree’s trunk: pretrained backbone exists → almost always start there. Branches differ in how much you unfreeze, and leakage risks live in the split (patient-level!) and in any test-time augmentation choices.
Solution

Decision tree: 1. Pretrained backbone for the domain exists (ImageNet-near for histology: yes) → start frozen: linear probe (train only a logistic head on backbone features). Evidence to gather: probe accuracy vs a classical baseline on engineered features. If probe ≈ ceiling → done; cheapest, least leaky. 2. Distribution gap large (staining, magnification, modality shift) or probe stalls → partial fine-tune: unfreeze the last block(s), small lr, keep early layers frozen (they carry generic edges/textures — 10.6’s transfer argument). Evidence: validation loss curve per unfrozen depth. 3. Many labels (≥ tens of thousands) or domain very far (e.g., astronomy from ImageNet) → full fine-tune with low lr everywhere + augmentation matching deployment. 4. Privacy/latency forbid cloud backbones → distill the backbone to a small net, or self-supervised pretrain on unlabeled local images (labels not needed for pretraining) then steps 1–3 locally.

Validation design: patient/subject-level splits (images from one sample never straddle train/test — the leak nobody sees in pixels); the frozen backbone’s pretraining data must not contain your test images (check provenance for public backbones on public benchmarks); every hyperparameter (unfrozen depth, lr, augmentation) chosen on validation folds, test touched once. The three strategies differ in how much prior you keep; the protocol differs not at all: representation learning moves the accuracy ceiling, honest validation decides whether you reached it.

7. Summary

  • Default order on tabular data: boosting → regularized linear/GLM → nets, in that order, with evidence at each promotion.
  • Deep learning’s home turf: perceptual/sequential/language structure + enough n or a transferable pretrained representation.
  • Small data + big nets fails quietly — check seed variance and validate before believing any leaderboard.
  • Interpretability, latency, and audit requirements are first-class model-selection criteria, not afterthoughts.
  • Every preprocessing step must live inside the CV fold; a leaky scaler inflates results by points, silently.
  • Match model class to truth geometry: sparsity→L1, boxes→trees, smooth→nets, structure→DL+transfer.
  • Judgment is the last skill — and the course continues with data that forces it: Part 11, survival analysis and censored data.
