8.4 Kernel SVM

The kernel trick is the SVM’s superpower: replace every inner product xᵢᵀxⱼ with a kernel function k(xᵢ, xⱼ) that implicitly computes inner products in a vast expanded space — nonlinearity without ever building the features. Circles in, circles classified; dimensions infinite, cost unchanged.

Tier 1 — every cell below runs live.

1. Basic Concept

The dual’s predictions depend only on inner products (8.2): f(x) = Σαᵢyᵢ⟨xᵢ, x⟩ + b. Substitute any valid kernel k:

\[f(x) = \sum_i \alpha_i y_i k(x_i, x) + b\]

The RBF (Gaussian) kernel — the default workhorse:

\[k(x_i, x) = \exp(-\gamma \|x_i - x\|^2)\]

2. Concept Questions

  1. State the kernel trick’s two-part bargain: what must the algorithm never do, and what may it only use?
  2. Why does the RBF kernel create closed, local boundaries while polynomial kernels create open, global ones?
  3. γ in the RBF kernel: what does large γ do to each training point’s influence, and which failure does extreme γ reproduce (7.1)?
  4. What makes a function a valid kernel (the Mercer condition, in one sentence), and name two practical consequences of validity.
  5. SVC.support_vectors_ after an RBF fit: are these points in the original space or the expanded one — and how many coordinates does the expanded space have?
Answers
  1. Never: materialize φ(x) or use any property of features beyond inner products. Only: inner products ⟨xᵢ, xⱼ⟩ (and ⟨xᵢ, x⟩ at prediction) — replace with k(xᵢ, xⱼ) and everything stays valid if k is a real inner product in some space.
  2. RBF similarity decays with distance (Gaussian bump around every SV): boundaries are unions of local closed contours — a point’s class is decided by nearby support vectors. Polynomials are global monomials: boundaries extend to infinity as open curves — decided by global orientation (6.3’s local-vs-global bases, kernel edition).
  3. Large γ → narrow bumps → each training point influences only its own micro-neighborhood → the fit approaches “memorize every point” — a 1-NN with kernels, the same overfitting endpoint (7.1’s k = 1).
  4. Valid = positive semi-definite: Σcᵢcⱼk(xᵢ, xⱼ) ≥ 0 for all coefficients — i.e., it IS an inner product in some Hilbert space. Consequences: the optimization stays convex (a QP), and predictions are consistent geometry (no paradoxical “similar to both classes” pathologies).
  5. Original space — support vectors are training points (stored as-is); the expanded space has infinitely many coordinates for RBF (the map is infinite-dimensional), which is exactly why you never build it.

Drills

Exercises (with solutions)

Exercise 1. Implement the RBF-kernel SVM’s prediction function by hand from a fitted SVC: extract dual_coef_, support_vectors_, intercept_; compute f(x) = Σ αᵢ k(xᵢ, x) + b yourself on a query grid; verify exact agreement with decision_function. Then confirm the kernel matrix your function implies (SVs × queries) matches rbf_gram — the whole model is these numbers.

Solution
A fitted kernel SVM is its support vectors, their dual coefficients, and an intercept — everything else (γ, C) shaped those numbers. This representation is also the deployment format: store ~n_support vectors, evaluate kernels on demand.

Exercise 2. The γ × C landscape: for the circle dataset, grid-search (γ, C) over log grids with 5-fold CV; display the CV-accuracy heat map. Identify the three regimes visible in the map (underfit smooth / well-fit / memorize), and mark the CV optimum. Then state the two-dial tuning recipe — which knob acts like model complexity, which like the fit-price — and their interaction.

Solution
Reading: low γ or low C → underfit (smooth blob, ~50–70%); high γ AND high C → memorize (train-perfect, CV-crippled); the diagonal ridge between them is the operating zone — γ sets per-point locality (complexity), C sets how hard violations are chased (fit price), and jointly they trace the 4.4 U-curve in 2-D.

Exercise 3. Kernel zoo, honestly compared: on three truths (linear, circle, XOR-corner), compare linear / poly(degree 2) / RBF kernels by CV accuracy — plus the “kernel + linear truth” sanity row. Report the 3(kernel) × 3(truth) table. Write the kernel-selection heuristic the table supports, including the role of the linear baseline as a lower-bound guard against needless kernels.

Solution
Reads: linear kernel wins its own truth and never embarrasses elsewhere (the guard); poly2 takes XOR (its basis contains x₁x₂); RBF wins circles and corners (local freedom) but gains nothing on linear truths. Heuristic: always run the linear baseline; reach for RBF when validation says the boundary curves; try poly when domain theory names the interaction order. Kernels are hypotheses about geometry — test them like hypotheses.

4. Advanced Information & Pitfalls

  • γ and C multiply each other’s effect — the same fit can be reached by (γ↓, C↑) or (γ↑, C↓) along the flat valley; tune jointly on log grids, never independently (4.6).
  • Scaling is non-negotiable: RBF distance is Euclidean in raw units; unscaled features decide the geometry (8.1’s law, now with teeth — γ’s meaning changes with scale too).
  • SV count explodes with overlap: RBF SVMs on noisy data can retain most of the training set as SVs — prediction cost and memory scale with it; LinearSVC or trees for huge n.
  • gamma="scale" (default) is 1/(n·Var(X)) — data-dependent, sensible, but changes between datasets: never port γ across problems.
  • Probabilities: SVC(probability=True) fits Platt scaling post-hoc (internal CV) — calibrated-ish but slower and slightly different model; quote decision_function for ranking, probabilities only after this step (3.7).
  • Precomputed kernels: you can pass your own Gram matrix (kernel="precomputed") — the door to custom/domain-specific similarity functions (strings, graphs, alignments) — validity (PSD) is on you.

What’s wrong, and the fix
  1. γ = 50 on unscaled data: distance² of typical points is tens-to-hundreds → kernel values ≈ e^{-thousands} ≈ 0 — every point isolated, training memorizes (train ≫ test). Scale features; tune γ on a log grid.
  2. One loss → verdict: the linear baseline is a guard, not a rival; on a circle truth it should lose, and kernels don’t “always win” — linear truths punish them (drill 3).
  3. Scores ≠ probabilities: decision_function is the unbounded margin; calibrate (Platt) if probabilities are needed downstream.

5. Advanced Questions

Q1. Verify the polynomial-kernel identity on a small case: for x, z ∈ R², k(x, z) = (xᵀz + 1)² equals ⟨φ(x), φ(z)⟩ for φ = (x₁², x₂², √2x₁x₂, √2x₁, √2x₂, 1). Check numerically across random pairs. Then explain why this equivalence means the explicit-map SVM and the kernel SVM are the same model — and construct (conceptually) the case where the explicit map is still preferable (name the resource that becomes the bottleneck).

Hint Expand (xᵀz + 1)² = (x₁z₁ + x₂z₂ + 1)² term by term; match coefficients to inner products of the φ coordinates.
Solution

(xᵀz + 1)² = (x₁z₁)² + (x₂z₂)² + 2x₁z₁x₂z₂ + 2x₁z₁ + 2x₂z₂ + 1 = x₁²z₁² + x₂²z₂² + (√2x₁x₂)(√2z₁z₂) + (√2x₁)(√2z₁) + (√2x₂)(√2z₂) + 1·1 — exactly ⟨φ(x), φ(z)⟩ for the stated φ. Numerics:

Same model: SVM-in-φ-space with a linear kernel ≡ SVM with (xᵀz+1)² — identical optimum, identical predictions. Explicit map preferred when φ is low-dimensional and you predict millions of times (basis evaluation beats SV-kernel sums) or need φ’s coefficients for interpretation; the kernel wins when dim(φ) is huge (degree 10 → ~66+ dims; RBF → infinite).

Q2. The γ–distance reading: show that for the RBF kernel, the decision function is a signed weighted sum of bumps centered at support vectors, and that γ determines each bump’s radius (∝ 1/√γ). Design and run the diagnostic: for a fitted RBF SVM, plot the decision function along a 1-D slice, mark SV locations, and show how the boundary interpolates between SV classes as γ varies over {0.2, 2, 20}. Write the “γ-as-resolution” sentence a practitioner should carry.

Solution
γ is the resolution dial of a bump-sum representation: 1/√γ is bump width. Low γ: one wide bump family — smooth, nearly-linear boundaries. High γ: a bump per point — the decision function reproduces training labels individually (memorization). Carry the sentence: “γ sets how far one training point’s vote reaches; C sets how expensive it is to disagree — tune them together.”

7. Summary

  • Kernel trick: predictions need only inner products — swap in k(xᵢ, xⱼ), get the expanded space for free.
  • RBF = local bumps (closed boundaries, γ = resolution); poly = global monomials (open boundaries); linear = the guard.
  • Scale features; tune (γ, C) jointly on log grids; the flat valley between underfit and memorize is the target.
  • Fitted model = support vectors + dual coefficients + intercept — deployable, inspectable, kernel-generic.
  • Valid kernels are PSD: convexity preserved, geometry consistent, custom similarities welcome.
  • Nonlinearity now costs a kernel choice, not a basis build — but probabilities, scaling, and SV-cost caveats ride along.
  • Linear SVM vs logistic, margins vs likelihoods, side by side: 8.5 SVM vs logistic regression.
