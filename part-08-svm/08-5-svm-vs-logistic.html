8.5 SVM vs Logistic Regression

Two linear classifiers, one hinge loss, one log loss. They agree on most datasets and diverge in exactly the dimensions that matter for deployment: probabilities, outlier sensitivity, margin geometry, and scalability. This page makes the comparison a decision procedure rather than a preference.

Tier 1 — every cell below runs live.

1. Basic Concept

Same linear score f(x) = wᵀx + b, different training losses:

\[\text{SVM: } \frac{1}{2}\|w\|^2 + C\sum_i \max(0,\, 1 - y_i f_i) \qquad \text{Logistic: } \frac{1}{2}\|w\|^2 + C\sum_i \log(1 + e^{-y_i f_i})\]

2. Concept Questions

  1. State what each loss does with a far-correctly-classified point (score = 4, y = 1) — and the boundary consequence of the difference.
  2. Both models output a signed score. Which one can you interpret as a log-odds, and why not the other?
  3. Overlapping classes with heavy outliers: which method’s boundary is more robust, and which loss property delivers that?
  4. Why does logistic regression scale to huge n more gracefully than SVC (two reasons — one statistical, one computational)?
  5. Your stakeholder needs “probability of disease.” Which model, which step, and what must you check afterwards?
Answers
  1. Hinge: loss 0 — the point vanishes from the fit (no gradient). Logistic: loss log(1 + e⁻⁴) ≈ 0.018 — small but nonzero, still pulling. Consequence: SVM’s boundary is set by frontier points only; logistic’s by every point, weighted by their surprise.
  2. Logistic’s f(x) is the fitted log-odds (by construction: p = σ(f)) — exponentiate coefficients for odds ratios. SVM’s score is a margin distance in canonical units — no probability or odds semantics attached.
  3. SVM — hinge’s linearity bounds any single outlier’s influence (its contribution grows linearly however far it strays), while logistic’s exponential tail lets extreme points dominate the gradient. (Robust variant: Huber/absolute-loss boosting, 7.5.)
  4. Statistical: logistic is a smooth convex GLM — efficient IRLS/SGD variants, warm starts, and it doesn’t need the dual’s kernel trick to stay exact. Computational: hinge-SVM’s dual scales with n (SV count grows with overlap); logistic’s primal has no such n-dependence, and SGDClassifier(loss="log_loss") streams.
  5. Logistic regression, then calibrate it (reliability check on held-out data — 3.7): logistic is the right starting point (native probabilities, no Platt detour), but calibration is still a checked property, not an assumption.

Drills

Exercises (with solutions)

Exercise 1. The outlier sensitivity dose-response: on separable data, add ONE mislabeled point at distance d ∈ {0.5, 1, 2, 4, 8} beyond the boundary. For each d, record the boundary shift (perpendicular displacement of the zero-set) for SVM (C = 1) and logistic. Plot shift vs d. Verify: SVM’s shift saturates (linear-in-d influence), logistic’s grows without bound. State the robustness rule this supports.

Solution
The SVM’s boundary barely moves (0.093 → 0.002 as the bad point recedes) while logistic’s shift grows and then saturates around 0.06–0.08. The saturation is the tell, and the last block explains it: for a misclassified point (\(\log(1 + e^{|z|}) \approx |z| - \log 2\) when \(|z|\) is large) the logistic loss grows linearly, just like the hinge — the printed ratio stays near 0.95 even 30 units out. The familiar “logistic is exponential, hinge is linear” contrast is about far-correct points (where \(\log(1+e^{-|z|})\) decays exponentially while the hinge is exactly 0), not about violations. So the real difference is a bounded, saturating response, not divergence. Two traps this exercise invites are worth naming: reading -intercept/coef off a scaler-wrapped pipeline silently returns standardized units (the raw-scale value is mean + scale × (-b/w)), and reading a saturated plateau as “grows without bound”. On mislabeled extremes, clean them first (2.10’s repair menu) — the loss choice is a second-order concern next to that.

Exercise 2. Probability quality, head-to-head: on a moderately overlapping dataset, compare (a) logistic’s native probabilities, (b) SVM + probability=True (Platt), (c) SVM’s raw decision_function rescaled by naive min-max — by Brier score, reliability curves, and AUC. Which wins calibration, which wins ranking, and does the ranking winner match the calibration winner? Conclude with the “probabilities vs scores” deployment rule.

Solution
AUC: identical or near-identical (monotone recalibrations preserve ranking). Brier/calibration: logistic and Platt-SVM are close; naive min-max rescaled scores are uncalibrated fiction. Rule: rank with whichever margin you like; probabilities require a model that produces them honestly (logistic) or an explicit calibration step (Platt/isotonic) — never a linear rescale of a margin.

Exercise 3. The scale-of-n crossover: generate datasets at n ∈ {500, 5,000, 50,000} (p = 10) and compare training time and test accuracy for LogisticRegression (liblinear/lbfgs) vs LinearSVC vs SVC(kernel=“linear”). Report the 3×3 table. Where does each become impractical, and what streaming/streaming-adjacent alternative (SGDClassifier with hinge/log losses) offers at 50k? Verify SGD’s accuracy is within ~1% of the batch solution.

Solution
Logistic and LinearSVC are both fast at these scales; SVC(kernel=“linear”) is the first to hurt (dual grows with n) — drop it for large n. SGD (hinge or log) trades a little accuracy for streaming-scale speed and stays within ~1% at 50k with a few passes. The scaling rule: probabilities + big n → logistic/SGD-log; pure decisions + big n → LinearSVC/SGD-hinge; SVC only when SVs themselves (or kernels) are the point.

4. Advanced Information & Pitfalls

  • Two regularizations, same λ-spirit: both penalize ‖w‖²; C (SVM) and C (logistic) are both 1/λ-style slack/tail prices — but their effects differ because the losses differ. Tune each on its own grid (4.6).
  • Hinge’s sparsity of influence is a feature (robustness, SV parsimony) and a bug (no per-point probability pressure, uncalibrated scores). Decide which you need before choosing the loss (3.1).
  • Logistic = canonical GLM: coefficients are log-odds ratios, inference exists (3.3); SVM coefficients are margin geometry, inference doesn’t (naively).
  • Both are linear: identical ceiling without feature engineering or kernels — the 6.3 dictionary, or 8.4’s trick, applies to both.
  • Class weighting differs subtly: SVM’s class_weight rescales slack prices; logistic’s resamples the loss — both fix imbalance directionally, verify with PR curves (3.1.5).
  • Multiclass paths differ: SVC does OvO (8.6); LogisticRegression does multinomial (softmax) by default — another semantic difference between “equivalent” pipelines.

5. Advanced Questions

Q1. The regularized-loss unification: write both SVM and logistic as penalized ERM with the same L2 penalty and different losses. Show formally that as C → ∞ (no regularization), both maximize the margin-like quantity in their own metric, and that the only difference is the loss’s tail behavior past the margin. Then construct a dataset where the two fits produce orthogonal boundaries (hint: one dominant outlier vs clean data — reuse the geometry of 8.2 Exercise 2).

Hint hinge’(f) = −y·1(yf < 1) — a constant push while outside the margin, then exactly zero; logistic’(f) = −y·σ(−yf) — the same constant push, but decaying smoothly and never reaching zero. Both are bounded in magnitude by 1; they differ in the tail, not in boundedness. Construct: two clean clusters + one mislabeled point at extreme distance; crank the loss weights and watch which boundary moves.
Solution Both minimize (1/2)‖w‖² + CΣL(yᵢfᵢ), and the only difference is the loss’s tail past the margin. Get that tail exactly right, because the usual phrasing of it is wrong. For a misclassified point both losses grow linearly: hinge \((1 - z)\) and logistic \(\log(1 + e^{-z}) \approx -z - \log 2\), and their ratio tends to 1. The exponential belongs to the other side: for a far-correct point the hinge is identically 0 while logistic’s loss is \(\approx e^{-|z|}\) — decaying but never exactly zero. That asymmetry is the real difference, and it is a statement about influence, not about growth rate: a single extreme mislabeled point contributes exactly zero SVM gradient once it is past the margin (the hinge is flat there, so the boundary is pinned by everything else), while logistic keeps a small persistent gradient forever. Hence the boundary is pinned for the SVM and slowly dragged for logistic — with the drag saturating, as Exercise 1’s table shows. The construction demonstrates “loss tails = influence tails”: choose the tail you can defend given your labeling process.

Q2. Decision-theoretic selection: a screening program (1% prevalence, FN cost 50× FP) needs (i) a ranked list for follow-up budget and (ii) per-patient risk estimates audited by regulators. Design the model comparison: which metrics for (i) and (ii) (3.1, 3.1.5), which two models to compete, what calibration step the winner needs, and how the cost ratio enters threshold choice after modeling (3.1 Exercise 2). Implement the comparison on simulated data and report the decision.

Solution
  1. Ranking for budget: AP/AUC on continuous scores — both models compete (SVM margins rank fine). (ii) Audited risks: logistic’s native probabilities + calibration check win (SVM needs Platt and still needs verification). Threshold: with FN:FP = 50:1, choose the cutoff from the cost-minimizing point of the chosen model’s ROC/PR trade — after modeling, on validation data, and reported with the confusion matrix it implies. Decision: logistic for the deployed risk model, SVM kept as the margin-consistency check.

Then write the two-sentence review response you’d file — the reusable text for the next paper you review with this flaw.

7. Summary

  • Same linear score, different loss tails: hinge (zero past margin, linear when wrong) vs log (never zero, exponential when wrong).
  • Probabilities: logistic native and interpretable; SVM via Platt — calibrate either way.
  • Robustness: hinge bounds outlier influence; logistic’s tail lets extremes pull — labeling quality decides.
  • Scale: logistic/LinearSVC/SGD for big n; SVC when SVs or kernels are the point.
  • Both are linear without engineering; both need scaling, honest tuning, and prevalence-aware metrics.
  • Multiclass paths differ (OvO vs multinomial) — see 8.6 next.
  • One family remains: SVMs for many classes at once — 8.6 Multiclass SVM.
