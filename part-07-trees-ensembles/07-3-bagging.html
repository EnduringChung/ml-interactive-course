7.3 Bagging

Bagging (bootstrap aggregation) fits many models on bootstrap resamples and averages them. Its entire logic is the variance decomposition of 4.4: averaging B unstable fits divides variance by ~B — and trees are the perfect fuel, unstable enough to benefit, cheap enough to grow hundreds.

Tier 1 — every cell below runs live.

1. Basic Concept

Given B bootstrap samples, fit \(\hat f^{(b)}\) on each and predict by the average (regression) or majority vote (classification):

\[\hat f_{\text{bag}}(x) = \frac{1}{B}\sum_{b=1}^B \hat f^{(b)}(x)\]

Why it works — for (approximately) uncorrelated, identically-distributed estimators:

\[\text{Var}(\hat f_{\text{bag}}) = \rho\sigma^2 + \frac{1 - \rho}{B}\sigma^2\]

where ρ is the pairwise correlation between trees. Averaging kills the second term; ρ (shared signal structure) sets the floor.

2. Concept Questions

  1. Why must bagging use bootstrap resamples rather than k fresh splits of the data — what does each replicate lose, and what does it gain?
  2. In Var = ρσ² + (1−ρ)σ²/B, what sets ρ, and which later method attacks ρ directly?
  3. Bagging is said to “reduce variance while leaving bias roughly unchanged.” Why roughly — when does bagging actually change bias?
  4. What is the out-of-bag (OOB) estimate, and which CV concept is it a bootstrap-flavored cousin of (4.3)?
  5. Your bagged tree ensemble extrapolates flat outside training x — same as one tree. Which property survived averaging (per 7.2)?
Answers
  1. Bootstrap resamples share rows (≈ 63% distinct) — each replicate is worse (trained on a sample of a sample) but available in quantity from one dataset. Fresh splits would give better individual models but you’d need a k× bigger dataset. Bagging trades per-model quality for ensemble quantity — a bargain only because averaging punishes independent noise, not individual skill.
  2. ρ = pairwise correlation between trees’ predictions — set by how strongly the same signal structure dominates every bootstrap fit. Random forests (7.4) attack ρ by forcing trees to consider random feature subsets, decorrelating them at the cost of slightly worse individual trees.
  3. The bagged average lives in the convex hull of the base fits — for squared loss, averaging can’t add bias outside the single-model bias pattern, but it can smooth the staircase into something closer to the truth (jaggedness was partly bias-like misfit of the piecewise-constant approximator), so effective bias often drops slightly — most visibly for unstable approximators of smooth truths.
  4. Each bootstrap fit never saw ≈ 36.8% of rows; predicting those OOB rows and aggregating gives a test-error estimate without a separate holdout — the bootstrap cousin of CV, free with the fit (4.5).
  5. Averaging preserves each base model’s support — predictions remain convex combinations of leaf means, so outside training x the ensemble is as flat as its members. Ensembles fix variance, not bias; the axis-parallel and no-extrapolation biases are inherited (7.2’s ledger).

Exercises (with solutions)

Exercise 1. Implement bagging from scratch (no sklearn ensemble classes) and verify it matches BaggingRegressor behavior: same B, same bootstrap draws (same rng pipeline), compare test MSEs within tolerance. Then decompose: report the average single-tree test MSE, the bagged test MSE, and the mean pairwise tree correlation ρ — check the variance formula ρσ² + (1−ρ)σ²/B approximately holds using σ² = mean single-tree squared-deviation.

Solution
The scratch version lands beside sklearn’s (differences: rng streams and sklearn’s internal bootstrap details). The variance story checks out to first order: bagged variance ≈ ρσ² + (1−ρ)σ²/B — and since ρ ≈ 0.6–0.9 for full trees, the floor ρσ² dominates — the number random forests exist to crush.

Exercise 2. Instability → benefit mapping: for stability-ranked learners (linear regression, depth-3 tree, full tree), bag each with B = 100 and measure the relative test-MSE improvement (single vs bagged). Report the 3-row table. Then state the bagging selection rule: which base learners deserve bagging, and what does the linear row predict about “bagging everything” as a workflow?

Solution
Improvement ordering is exactly the instability ordering: full tree gains hugely, depth-3 moderately, linear ~zero (sometimes slightly negative — averaging stable learners adds nothing and the bootstrap samples’ mild quality loss can dominate). Rule: bag unstable, low-bias learners; don’t bag a stable model for accuracy (do it only for uncertainty quantification via OOB, or to parallelize).

Exercise 3. OOB as an honest validator: for one dataset, compare (a) the ensemble’s OOB score, (b) 5-fold CV of the same bagging procedure, and (c) true test error on fresh data. Repeat over 100 dataset draws; report mean and SD of each estimator’s error-in-estimating-the-truth. How does OOB’s accuracy as an estimator compare with 5-fold CV, and at what compute price?

Solution
OOB tracks the truth nearly as well as 5-fold CV while costing zero extra fits — the bootstrap samples are already there. (Details differ: OOB is R²-based by default and uses ≈63%-sized training sets like 4.5’s .632 discussion.) For ensembles specifically, OOB is the default internal referee — with nested CV still required when the procedure itself is tuned (4.6).

4. Advanced Information & Pitfalls

  • More trees never hurt (accuracy-wise): bagged test error decreases monotonically in B and plateaus — B is a compute dial, not a tuning dial (7.5 breaks this rule: boosting can overfit with B).
  • ρ is the enemy: bagging full-grown trees on wide data yields highly correlated trees (the strong feature wins every bootstrap) — the variance floor stays high. max_features < 1 decorrelates and becomes… a random forest (7.4).
  • OOB subtleties: OOB estimates each row’s prediction from ≈ B·0.368 trees (not all B) — slightly noisier and more pessimistic than the full ensemble; fine for monitoring, tuned-claim rules still apply.
  • Averaging kills calibrated-by-construction class fractions: bagged classification votes are fractions of trees, not of data — probability calibration still needs checking (3.7).
  • Bagging linear models ≈ feature subspace ensembling — occasionally useful for stability selection vibes, useless for accuracy (drill 4/Exercise 2’s law).
  • Bias interactions: because bootstrap trees are trained on ≈63% distinct rows, each is weaker; for stable-but-high-bias learners, bagging can even hurt — measure, don’t assume.

5. Advanced Questions

Q1. Derive the bagged-variance formula: for B i.i.d. estimators with variance σ² and pairwise correlation ρ, show Var(mean) = ρσ² + (1−ρ)σ²/B, and hence the plateau as B → ∞ is ρσ². Then verify by simulation for bagged trees: estimate ρ and σ² from an ensemble’s prediction matrix, predict the B → ∞ plateau, and compare against the empirical B = 500 error. What does this decomposition predict about the relative value of adding trees to a forest with B = 10 vs B = 1000?

Hint Var(mean) = (1/B²)[Bσ² + B(B−1)ρσ²]; divide and split into diagonal + off-diagonal terms.
Solution

Var(mean) = (1/B²)(Bσ² + B(B−1)ρσ²) = σ²/B + ρσ²(1 − 1/B) = ρσ² + (1−ρ)σ²/B — diagonal variance dies as 1/B; the correlated floor ρσ² never does. Simulation:

The marginal value of a tree decays like (1−ρ)σ²/B: at B = 10 each addition still matters; past a few hundred, more trees buy smoothness of the OOB aggregate, not accuracy — spend compute on ρ (random forests) or on sequential bias-fitting (boosting, 7.5) instead.

Q2. Bagging and bias for smooth functions: theory says averaging convex combinations can’t increase squared bias, but for trees it often decreases it. Verify: measure bias² of a single depth-unlimited tree vs a B = 200 bag of them (multi-training-set protocol of 4.4) on the sinusoid, and explain the mechanism — averaging piecewise constants with different cutpoint locations approximates a smoother function whose expected value lands nearer f. Then state when bagging would leave bias untouched.

Solution

Different bootstrap trees cut at slightly different x’s; their average has cutpoints spread — an effective finer partition whose mean function tracks the smooth truth better. Note the sign of the measured effect: bagging’s bias² goes up slightly (0.00116 → 0.00177), not down and not flat. That is the expected direction, and it is exactly what sklearn’s own reference example reports for this estimator on a comparable 1-D problem:

Tree:          0.0255 (error) = 0.0003 (bias^2) + 0.0152 (var) + 0.0098 (noise)
Bagging(Tree): 0.0196 (error) = 0.0004 (bias^2) + 0.0092 (var) + 0.0098 (noise)
Bias² up (0.0003 → 0.0004), variance down by 40% (0.0152 → 0.0092), noise untouched, total error down. Averaging step functions rounds off the step edges, which costs a little bias on a smooth truth while buying a large variance reduction. Bagging leaves bias essentially unchanged when the base model is stable (linear models: the bootstrap fits barely differ, so the average equals one fit) or when the truth is itself piecewise-constant aligned with typical cuts. The headline: bagging changes the bias/variance mix in practice — “variance-only” is the textbook simplification, not the measurement, and the bias cost is real but small. Getting any of these numbers at all requires that the bootstrap index be shared between x and y; drawing two independent indices pairs each x with a random stranger’s y, and the “bagged” model then looks catastrophically biased (a 400× error) for reasons that have nothing to do with bagging.

6. Complex Questions

C1 (bagging × 4.4 bias–variance). Decompose bagging across B: with the multi-training-set protocol, estimate bias²/variance for B ∈ {1, 5, 25, 200} bagged full trees. Confirm variance falls ~ (ρ + (1−ρ)/B) while bias² drifts slightly down; overlay the total. Then answer: at which B does adding trees stop mattering for your data, and how does that B scale with the base tree’s instability?

C2 (bagging × 3.7 comparison × 9.x). Bagged classifiers and calibration: fit a bagged tree classifier (B = 200 vote fractions) on an imbalanced problem; evaluate AUC, Brier, and a reliability diagram against a single tree and a logistic model. Explain mechanistically why vote-averaging improves the Brier score (votes average out leaf-fraction noise) yet still trails logistic calibration — and design the calibration step you’d add before deployment.

7. Summary

  • Bagging = bootstrap + average: variance ÷ B for the independent part, ρσ² floor for the correlated part.
  • Works exactly as well as the base learner is unstable — trees are the canonical fuel; linear models don’t benefit.
  • B is compute, not tuning; the plateau is set by ρ, which random forests (7.4) attack directly.
  • OOB gives a free internal validation estimate — the bootstrap’s gift to ensembles (4.5).
  • Bias is roughly preserved — and measurably slightly improved for unstable approximators of smooth truths.
  • Inherited unchanged: axis-parallel bias, flat extrapolation, vote-fraction calibration caveats.
  • The floor ρσ² is the target now: force trees to disagree — 7.4 Random forests.
