7.4 Random Forests

Random forests = bagged trees (7.3) plus random feature subsampling at every split. The extra randomness decorrelates the trees — attacking the ρσ² floor that plain bagging can’t touch — and produced the most reliable off-the-shelf learner for tabular data of its era.

Tier 1 — every cell below runs live.

1. Basic Concept

Two randomness sources per tree: (1) a bootstrap sample (7.3); (2) at each split, only max_features (mtry) randomly-chosen features may be considered. The second is the forest’s signature — trees are forced to disagree:

2. Concept Questions

  1. State precisely what max_features does at each split, and why forcing trees to be weaker can make the forest better.
  2. Standard defaults: mtry = √p for classification, all p features for regression. What trade produces each? (Careful: p/3 is Breiman’s classical suggestion for regression, but it is not sklearn’s default — RandomForestRegressor().max_features is 1.0.)
  3. Why don’t random forests overfit when you add more trees — and which earlier ensemble violated that?
  4. OOB error vs CV error for a forest: when do they agree, and what procedure detail (not the error estimate itself) makes them differ?
  5. Two features are near-duplicates. What happens to (a) impurity importances, (b) the model’s predictions?
Answers
  1. Each split may only consider mtry randomly-drawn features; if the strong feature isn’t in the draw, the tree must split on something else — producing a different tree. Individually worse (weaker splits), collectively decorrelated: in ρσ² + (1−ρ)σ²/B terms, ρ drops enough that the (1−ρ)/B term’s collapse dominates.
  2. The trade is per-split quality vs decorrelation. Classification: √p candidates usually include enough signal to keep splits decent while decorrelating across p choices. Regression: p/3 — regression signals are typically spread over more features, needing wider draws.
  3. Adding trees only averages more draws from the same randomized procedure — Var → ρσ² + (1−ρ)σ²/B monotonically decreasing, no overfitting term in B. Gradient boosting (7.5) fits trees sequentially to residuals, so more trees keep changing the function — and can overfit.
  4. They estimate the same quantity (test error of the procedure) by the same principle (out-of-sample rows). They differ in mechanics: OOB uses ≈ 0.368B trees per row and bootstrap-sized training sets, CV uses full ensemble and (K−1)/K-sized sets — so numbers differ by a few percent while conclusions rarely do.
    1. Impurity importances split the credit arbitrarily between the twins (each mirrors the other; whichever is drawn first takes the share) — importances are diluted and unstable; (b) predictions are essentially unaffected — the forest uses the shared signal whichever twin carries it. Interpretation is where duplicates hurt, not prediction.

3. Drills & Exercises

Drills

Predict, then run.

Exercises (with solutions)

Exercise 1. The decorrelation dividend, isolated: on a non-linear classification truth, compare bagging (all features) against forests at max_features = 3 and 1, reporting both test accuracy and the average pairwise correlation between member-tree predictions. Verify that the accuracy gain tracks the ρ drop — the ρσ²-floor argument made empirical. Then, as the diagnostic half of the exercise, re-run the same comparison on a linear truth of identical size and explain why the effect vanishes. (Getting the DGP right is most of this exercise; a linear truth cannot demonstrate the mechanism at all.)

Solution

Here the ρ argument works, and the whole chain is monotone: bagging (every feature, so near-clone trees) sits at ρ = 0.317 and 0.8595 accuracy; cutting mtry to 3 drops ρ to 0.290 and lifts accuracy to 0.8745; mtry = 1 drops ρ to 0.210 and reaches 0.8765. Lower ρ, better predictions — exactly the ρσ² floor of 7.3, with the per-tree σ² held fixed because every tree still sees all of some features.

The dataset choice is doing more work than it looks. An earlier version of this exercise used a linear regression truth on Gaussian features, and there the effect vanished — mtry = 1 came out 3× worse than mtry = p, and the honest-looking conclusion was “decorrelation doesn’t pay.” That conclusion was an artifact. When the truth is a linear function of all features, every feature carries the same kind of information, all splits are near-equally good, and limiting mtry can only starve the tree — the σ² blow-up swamps any ρ gain, which is precisely the caveat the ρ formula carries. The dividend requires a truth where different feature subsets give genuinely different, individually-useful trees, i.e. a non-linear boundary. So the rule is not “small mtry is good” but “small mtry is good when the boundary is not axis-parallel — and that is a property of the problem you can only learn from the data.” This is also why sklearn ships no max_features example: the effect is conditional, and a demo on the wrong DGP teaches the wrong lesson.

Exercise 2. Importance forensics: on data with (a) one signal feature, (b) its near-duplicate twin, (c) 18 noise features, compare impurity importances vs permutation importances (permutation_importance computed on a held-out set). Report both rankings’ treatment of the twins and the noise. Which importance answers “which feature does the model use” and which answers “which feature helps predictions”?

Solution
Impurity importance splits credit between twins (whichever is drawn first claims the split, starving the other) and inflates noise features with many split opportunities. Permutation importance on held-out data answers the deployment question — breaking f1 breaks predictions because f0 alone (fitted with a twin present) doesn’t fully carry the mapping — while correctly zeroing noise. The two questions are different; quote the one you mean.

Exercise 3. The honest forest workflow: build Pipeline(StandardScaler-optional, RandomForest) — deliberately without scaling (defend the choice) — tune max_features and min_samples_leaf by inner CV, evaluate by outer nested CV, and report OOB alongside. Apply to a 600-feature, 100-row problem (5.6 territory). Write the three-sentence summary comparing the forest to your Part 5 linear winners on accuracy, assumptions, and interpretation.

Solution
Summary template: “The random forest matched the penalized linear models’ nested-CV accuracy without linearity or scaling assumptions, at the cost of coefficient interpretability; its per-feature importances are advisory, and its OOB estimate tracked nested CV within noise. On n = 100, p = 600 data both families are viable; the choice is driven by the shape of the signal (sparse-linear → lasso; interaction-rich → forest) rather than by leaderboard deltas.”

4. Advanced Information & Pitfalls

  • OOB is not a license to tune on everything: OOB can pick hyperparameters weakly, but heavy tuning against OOB re-inflates selection optimism (4.6); nested CV for claims.
  • Impurity importance’s bias: favors continuous/high-cardinality features and splits credit arbitrarily under correlation — permutation importance on held-out data is the defensible default (Exercise 2).
  • n_estimators is compute, not tuning: more trees monotonically help (plateau); tune max_features, min_samples_leaf, max_depth — the variance/correlation dials.
  • Regression forests can’t extrapolate (leaf means, 7.2): trending time series need detrending or different tools.
  • Probabilities: forest class fractions average many noisy leaf estimates — better than one tree, still not calibrated; check reliability (3.7).
  • Missing values: classic sklearn forests need imputation; HistGradientBoosting (7.6) handles NaN natively — a practical deciding factor in messy pipelines.
  • Class imbalance: forests inherit tree biases; class_weight="balanced" or stratified sampling — then evaluate with AUC/PR (3.1, 3.1.5).

What’s wrong, and the fix
  1. Five trees: more trees monotonically improve — B is a compute setting (≥ a few hundred); report the plateau, not a 5-tree straw model.
  2. B is not a tuning parameter — sweeping it on test burns the test set for nothing. Fix B by compute budget; tune max_features/min_samples_leaf by inner CV.
  3. Importances ≠ causation (and are unreliable under correlation): if features 5/6 are near-duplicates of feature 0, impurity importance fragments across them. Use permutation importance on held-out data, disclose correlation structure, and claim “model relies on,” never “causes.”

5. Advanced Questions

Q1. Derive the forest’s OOB prediction for row i: the average over trees whose bootstrap sample excluded i, and show its expected training-set size per OOB prediction is ≈ 0.368B trees on ≈ 0.632n rows. Then verify empirically that OOB error estimates the error of the 0.632n-trained forest, not the full-data forest, by comparing OOB against honest test error as n grows (n ∈ {50, 200, 800}) — the 4.5 Q1 mismatch, in forest clothing. At which n is OOB’s pessimism negligible?

Hint Each row is OOB with probability (1 − 1/n)ⁿ → e⁻¹; the OOB prediction averages only the trees that didn’t train on it.
Solution

OOB row i uses trees B_b with i ∉ bootstrap_b: a fraction (1−1/n)ⁿ ≈ 0.368 of B trees, each trained on a bootstrap of all n rows excluding i’s influence — effectively ≈ 0.632n-row models.

The OOB gap shrinks as n grows — at a few hundred rows it’s negligible, at n = 50 it’s a visible pessimism tax. Report OOB as the free monitor; spend a holdout or CV when the claim matters.

Q2. Why does mtry = 1 sometimes win? Construct a truth with exactly one strong feature and many weak ones; sweep mtry ∈ {1, 2, 4, 8, p} and plot test error. Explain the U-shape via ρ and per-tree quality (the 7.3 formula: variance floor = ρ(mtry)·σ²(mtry) with both terms mtry-dependent). Then state the symptom-based default: if your forest at default mtry underperforms a single pruned tree, which direction do you move mtry and why?

Solution

The contrast is the answer. On the non-linear boundary the sweep is monotone and decisive: bagging 0.8435 → mtry = 10: 0.8440 → mtry = 5: 0.8480 → mtry = 2: 0.8570 → mtry = 1: 0.8695, a 2.6-point gain over bagging, with every step in the predicted direction. On the linear twin the same sweep is nearly flat and non-monotone: 0.7515 (bagging) → 0.7585 → 0.7645 → 0.7680 → 0.7555, a total spread of about 1.3 points with an interior optimum and the smallest-mtry end worse than the largest. Same data size, same feature count, same metric, same code — only the geometry of the truth changed, and the character of the hyperparameter flipped.

The mechanism is the one from 7.3. Decorrelation pays only when the trees are individually good but redundant. When the truth is a linear function of all features, every split candidate is nearly as useful as every other, so feature-subset variation yields trees that are neither much better nor genuinely different — ρ falls a little, σ² rises a little, and the two roughly cancel (the flat interior optimum). When the truth is non-linear, different feature subsets really do produce different useful trees, so cutting mtry buys a large ρ drop at modest σ² cost. Two practical rules. Tune max_features by CV, never by a rule of thumb — and expect the knob to matter a lot on non-linear problems (interactions, trees, images, nonlinear genomic effects) and little on linear ones. And the diagnostic when your forest ties or loses to plain bagging: check whether your boundary is actually non-linear before concluding the forest is broken.

6. Complex Questions

C1 (forest × 5.6 high-dimensional). Forest vs lasso rematch with mixed truth: n = 120, p = 300, where 6 features are sparse-linear, 3 contribute only through interactions, and 1 has a threshold effect. Nested-CV both (lasso on raw features; forest), report test MSE and each method’s recovery of the three signal types (linear coefficients for lasso; importances for forest). Which truth components favor which method — and what ensemble-plus-lasso combined workflow would you pre-register?

C2 (forest × 3.6 GLM × 6.7 GAM). Interpretability triangulation: on a truth with one smooth effect + one interaction + one threshold, fit forest, GAM, and GAM+interaction-term. Compare CV MSE and each method’s recovery of the smooth component (correlate forest partial-dependence and GAM’s \(s_1\) with truth). Write the reporting rule: which model for the coefficient table, which for the black-box check, and what agreement between forest-PD and GAM smooths certifies about the additive assumption (6.7 C2’s triangulation, formalized).

7. Summary

  • Forest = bagged trees + mtry-limited splits: decorrelation attacks the ρσ² floor bagging can’t.
  • mtry is the key dial (√p for classification, all-features for regression in sklearn; Breiman’s p/3 is a suggestion, not the default): too small starves splits, too large clones trees.
  • n_estimators is compute; more trees never overfit — boosting will break that rule next page.
  • OOB: free internal validation, tracks CV closely, slightly pessimistic at small n.
  • Importances: impurity-based ones fragment under correlation; permutation-on-held-out is the defensible kind — and neither is causal.
  • Inherited from trees: no extrapolation, scale-invariance, uncalibrated probabilities; new superpowers: interactions and nonlinearity by default.
  • The sequential alternative: fit trees to residuals and climb — 7.5 Gradient boosting.
