7.1 Decision Trees

A decision tree predicts by asking a sequence of yes/no questions about the features, splitting the data into ever-purer regions. It is the first model in this course that learns its own basis functions — the adaptive step functions of 6.2, with cutpoints chosen by greedy RSS/impurity reduction — and the atom from which the most successful tabular learners (Parts 7.3–7.6) are built.

Tier 1 — every cell below runs live.

1. Basic Concept

Growing a tree = recursive binary splitting: at each node, search every feature × every cutpoint for the split that most reduces impurity — RSS for regression, Gini or cross-entropy for classification:

\[\text{Gini}: \; G = \sum_k \hat p_k (1 - \hat p_k), \qquad \text{RSS} = \sum_{i \in R} (y_i - \hat y_R)^2\]

Grow deep, then prune back (cost-complexity: minimize RSS + α·|leaves|) — because a fully grown tree interpolates its training data (4.1).

2. Concept Questions

  1. Why grow deep and then prune, rather than stopping early at “no split looks useful”?
  2. The greedy split at the root maximizes immediate impurity reduction. Construct (in words) a truth where this misses the optimal first split.
  3. What exactly does min_samples_leaf trade, and how does it differ in spirit from max_depth?
  4. A tree needs no feature scaling — why, and which earlier models contradicted that requirement?
  5. Your tree’s regression fit is piecewise-constant, so predictions within a leaf don’t move. Name two modeling consequences.
Answers
  1. Early stopping is myopic: a split that looks useless now enables a powerful split one level down (the XOR/interaction structure of 2.7). Grow-full-then-prune evaluates subtrees globally against data via cross-validated α — a better search over tree sizes than greedy stopping.
  2. Two features where the best pair of splits is diagonal but each single split is weak: e.g. class = “x1 XOR x2 > 0”. Any first axis-parallel split leaves both children 50/50 (zero impurity gain), so greedy stops — while a diagonal cut at 45° separates perfectly. Trees can still represent XOR with two levels, but greedy search needs luck (or the data volume) to find it.
  3. Both limit complexity, but min_samples_leaf enforces a data-density guarantee (every prediction rests on ≥ m observations — stable leaf means, honest confidence), while max_depth caps interaction depth regardless of density. Deep-but-wide and shallow-but-narrow are different failure shapes.
  4. Splits compare features via ordered thresholds — invariant to any monotone rescaling. Ridge/lasso/PCA/KNN all depended on magnitudes/distances (5.2, 0.5); trees don’t, which is also why they’re forgiving with mixed units.
    1. The response is discontinuous at every split — an artifact unless the world truly steps (6.2); (b) smooth trends are approximated as staircases — many leaves needed for accuracy, and derivatives are zero inside leaves. Model averaging (7.3) smooths both problems.

3. Drills & Exercises

Drills

Exercises (with solutions)

Exercise 1. Pruning, done properly: grow a full tree on noisy regression data (n = 150), extract the cost-complexity path, and select α by 5-fold CV over the path. Report (a) leaves and test MSE for the unpruned tree, (b) for the CV-pruned tree, (c) for the true-model oracle (degree-known step fit). Then state what pruning bought and what it cost.

Solution
Pruning removes the interpolation tail (hundreds of leaves → a handful), recovering most of the achievable accuracy; the cost is a few hundredths of MSE vs the theoretical best plus one CV loop. This grow-then-prune is the template every ensemble in this part inherits.

Exercise 2. The greedy trap, demonstrated: build the diagonal-separability truth — classes split by the line x₁ + x₂ = 0 with noise — and fit trees of depth 1, 2, 4. Plot boundaries and report test accuracy. Then fit a rotated model: tree on features (x₁+x₂)/√2, x₁ (a basis trick from 6.3). Write the lesson about axis-parallel bias and what fixes it (rotation, ensembles, or kernels — 8.4).

Solution
A single depth-1 stump on raw features is near a coin flip (the diagonal truth gives no axis-parallel purchase); depth 4 stitches four axis-parallel cells into a staircase approximating the line. One rotated feature makes a stump near-perfect. Axis-parallel greediness is the tree’s bias; basis rotation, oblique trees, ensembles of perturbed trees, or kernel methods are the standard remedies — each paying a different price.

Exercise 3. Impurity zoo: fit classification trees with criterion="gini" vs "entropy" on the same 6 datasets (varying class overlap and balance), comparing test accuracy and tree size (leaves). Then implement Gini by hand for a node with class proportions p and verify against tree.compute_feature_importances-style arithmetic on one split: predict the impurity drop of a candidate split manually and confirm it matches the reduction the fitted tree realized at that node (via tree_.impurity).

Solution
Gini vs entropy: cosmetic — the criteria are nearly proportional for two classes; neither fixes greediness or axis-alignment (the real tree biases). The hand computation is the whole learning algorithm in four lines: weighted impurity drop, maximized over splits.

4. Advanced Information & Pitfalls

  • Instability is the defining flaw: resample the data and the root split can move to a different feature entirely — small structural changes, big prediction changes. This is precisely what bagging (7.3) exploits and cures.
  • Impurity-based feature importances are biased toward high-cardinality/continuous features and unreliable under correlated features (7.4 covers the fix: permutation importance).
  • No extrapolation: regression trees predict leaf means — flat outside and between (2.1’s warning at its extreme); time-trended data needs care (or linex tricks).
  • Unbalanced classes: deep trees isolate rare-class pockets happily; use class_weight="balanced" or stratified evaluation (3.1).
  • random_state matters more than it should: tie-breaking among equally-good splits is random — pin seeds for reproducibility, but note ties indicate the data doesn’t care which split it got.
  • Interpretation caveat: a single small tree is genuinely interpretable (export_text); a deep tree is a maze — “interpretable model class” ≠ “this particular 500-leaf object is readable.”

5. Advanced Questions

Q1. Regression trees are adaptive step functions — show it: prove that a depth-d tree partitions the feature space into ≤ 2^d rectangles and predicts the mean of each. Then verify numerically that for a single feature, the depth-1 stump’s chosen threshold equals the RSS-minimizing split over all candidate cutpoints (compute both by brute force). What does the greedy-vs-exhaustive distinction cost when splits interact (2.7)?

Hint Induction on depth for the partition; for the stump, each candidate cut creates two means — compute RSS directly.
Solution

Each internal node splits a rectangle into two rectangles by one threshold, so depth-d yields ≤ 2^d disjoint rectangles, and each leaf’s prediction is its training mean — a piecewise-constant function (6.2 with data-chosen boundaries). For the stump:

They match to the candidate grid. Greediness costs nothing at the stump (exhaustive over one variable’s cutpoints is cheap); the bill arrives with interactions: the best pair of splits may look worthless individually (2.7’s XOR), and greedy trees find such structures only when data volume makes intermediate gains real — the honest argument for deeper search or ensembles.

Q2. Cost-complexity pruning as a regularization path: relate the ccp objective RSS(T) + α|T| to ridge’s penalty (5.2) — what is the “norm” being constrained (|T| = leaf count = L0-style), and why does the α-path exist as a finite sequence of distinct trees (verify: len(path.ccp_alphas) ≪ 2^leaves)? Then plot test MSE vs α on one dataset and mark the CV choice — identifying the U-curve of 4.1 in tree space.

Solution

ccp penalizes the L0 “norm” of the tree (number of leaves) — combinatorial regularization, vs ridge’s smooth L2. The key fact: as α increases, the optimal subtree changes only at O(#internal nodes) critical values — the whole pruning path is computable in one pass (that’s what cost_complexity_pruning_path returns), not a search over 2^leaves subsets.

Same U-curve, same CV discipline — pruning is regularization where the penalty counts leaves instead of coefficient mass, and the path algorithm is what makes it tractable.

7. Summary

  • Trees = greedy recursive partitioning: impurity-drop splits, grow deep, prune by cost-complexity.
  • Adaptive axis-parallel step functions: no scaling needed, interactions reachable in depth, boundaries always rectangular.
  • Default = interpolation: pruning (ccp_alpha via CV) is not optional.
  • Greedy search misses XOR-style structures at shallow depth; basis rotation or ensembles compensate.
  • Single trees are unstable — a flaw so central that the next three pages turn it into a superpower.
  • Piecewise-constant predictions: no extrapolation, no smoothness — fine for regimes, wrong for trends.
  • The fix for instability without losing adaptivity: average many trees — 7.2 Advantages & limitations first catalogues what we’re averaging.
