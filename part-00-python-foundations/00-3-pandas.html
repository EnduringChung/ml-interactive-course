0.3 pandas

NumPy arrays are fast but anonymous — columns have no names, rows have no identity, and mixed types are impossible. pandas adds labels. It is the Python twin of R’s data frame (the tidyverse’s tibble), and it will be your main tool for loading, cleaning, and summarizing data before any model sees it.

1. Basic Concept

2. Concept Questions

  1. What is the difference between df["expr"] and df[["expr"]]?
  2. When do loc and iloc give different answers for the same-looking call?
  3. Why does df[df["expr"] > 10]["expr"] = 0 silently fail to change df?
  4. What does how="left" in merge guarantee, and what can it create?
  5. What does df.groupby("tissue")["expr"].transform("mean") return, and how is it different from .mean()?
Answers
  1. df["expr"] returns a Series; df[["expr"]] returns a one-column DataFrame. Many methods (.T, joining, multiple columns) behave differently on the two.
  2. When the index labels are not 0..n-1 (e.g. after filtering, or a named index). loc["S2", ...] finds the row named S2; iloc[1, ...] finds the second row whatever it’s called.
  3. Chained indexing: the first bracket may return a temporary copy, so the assignment can land on a copy that’s then discarded (the classic SettingWithCopyWarning). The correct form assigns through one loc call: df.loc[df["expr"] > 10, "expr"] = 0.
  4. Left merge keeps every row of the left table; rows with no match on the right get NaN in the right columns (a merge “fan-out” can also multiply rows if the key is duplicated on the right).
  5. transform("mean") returns a Series the same length/index as df — the group mean broadcast back to each row — so you can subtract it to center within groups. .mean() returns one row per group.

4. Advanced Information & Pitfalls

  • Chained assignment is the #1 pandas bug. df[df.a > 0]["b"] = 1 may write to a temporary copy. Always: single loc call → df.loc[mask, "b"] = 1. (pandas 3.0’s copy-on-write makes chained assignment fail loudly; the pyodide pandas here is 2.x, where it can still silently no-op.)
  • inplace=True is deprecated style. It mutates the object you may not own and prevents method chaining. Prefer df = df.dropna() or df.dropna(subset=["marker"], inplace=False).
  • Index is not “row number”. After filtering, .iloc[0] and .index[0] diverge. Reset with reset_index(drop=True) when position and label must agree again.
  • merge can silently multiply rows if the key is duplicated on either side — always check len(result) vs len(left) and result["key"].value_counts().
  • == on a column with NaN gives False, never NaN: df[df["x"] == np.nan] matches nothing. Use df["x"].isna().
  • Object dtype columns are slow (Python objects, not arrays). Convert strings to category when few distinct values; parse dates with pd.to_datetime immediately.
  • groupby drops groups containing NaN keys by default (dropna=True) — a silent row-loss channel in reports.

5. Advanced Questions

Q1. A colleague merges a 20,000-row measurements table with a 200-row annotation table and the result has 23,117 rows. Diagnose the likely causes and give a defensive merge recipe.

Hint What does validate= in merge do? What does a duplicated key do to row counts?
Solution The key is duplicated: an m-to-many join multiplies rows (each left row matches every right row with the same key). Diagnosis: anno["gene"].value_counts().head(), compare len(left), len(right), len(merged); check merged["gene"].is_unique. Defensive recipe: merged = meas.merge(anno, on="gene", how="left", validate="m:1") — raises instead of fanning out; or deduplicate anno.drop_duplicates("gene") first; assert len(merged) == len(meas) afterwards. Choosing validate is documentation and a runtime guard.

Q2. Explain the difference between apply, transform, and agg on a groupby object, and why apply is the dangerous one. Give a task where apply is genuinely required.

Solution agg collapses each group to one value (len = n groups). transform returns one value per input row (len = n rows, group statistic broadcast back). apply returns whatever your function returns — a scalar, a Series, or a DataFrame — so pandas has to guess how to assemble results, which is slower and produces surprising shapes/indexes. Use agg/transform whenever possible; reach for apply when you need genuinely per-group multi-row computation, e.g. fitting a per-group linear model and returning its coefficients as a Series: df.groupby("site").apply(lambda g: pd.Series(np.polyfit(g["x"], g["y"], 1), index=["slope", "intercept"])). In modern pandas, prefer groupby(...).filter(...) for row selection and named agg for summaries to keep types predictable.

7. Summary

  • A DataFrame is labeled columns of Series sharing an index; dtypes tells you what you actually have.
  • loc = labels, iloc = positions; filtering is df.loc[mask, cols] — one call, no chaining.
  • groupby + agg/transform covers split–apply–combine; transform broadcasts back to row shape.
  • merge(how="left", validate="m:1") with NaN-counting afterwards is the safe join recipe.
  • NaN: use .isna(), skipna defaults, and decide drop-vs-fill deliberately.
  • Wide is for humans, long is for machines; melt/pivot convert between them.
